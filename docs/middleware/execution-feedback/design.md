# 规则拒绝的LLM执行反馈

规则字段、真实拒绝元数据、中间层消费接口和有条件的Flow回传已实现；通用OpenClaw执行上下文桥未实现。[架构](architecture.md)划分职责，[技术](technical.md)定义消费方式；不恢复旧MCP草案。

## 目的

规则作者预先配置固定拒绝提示，例如“AS已阻止读取该受保护目录，请停止重复尝试此操作。”实际拒绝后，将配置原文随对应工具结果交给LLM，减少重复调用和无效token消耗。不动态生成、插值、改写或让另一个模型解释原因；不宣称模型一定遵从或承诺节省数量。

文本属于[规则的唯一字段](../../backend/rules/technical.md#固定拒绝提示)，直接拒绝和Ask最终拒绝共用。用户选择允许、原操作未完成或仅提出拒绝时不反馈。超时实际拒绝仍取同一规则文本，不能改称用户已经点击拒绝。

## 用户与模型看到的行为

规则编辑界面直接编辑固定文本，空串就是没有文本；配置保存与采用状态仍按原规则回执。命中后使用原版本的文本，热更新不改已经发生的拒绝解释。

应用仍收到系统实际错误，AS不把errno改成文本，也不伪造应用的成功／失败状态。反馈附加到应用随后发给LLM的对应工具执行完成上报，保留原工具内容、ID、角色及原始观察；不新造system／developer消息，不改应用源码／SDK，不另发模型请求。

没有明确工具关联时保留来源缺口和未发送；目标内容已发出或连接不支持修改时保留对应未采用原因，实际I/O失败另按原事实报告。已经阻止的原操作不回滚，也不为发送反馈放开被规则禁止的连接。终止了应用／父进程且没有后续合法消息时，不把提示转给另一个实例。

## 本次设计范围

正式消息消费者在原真实完成提交后发起固定反馈；只有已核实的 ToolExecution 才进入 Flow。原 Ask、答案和执行结果仍独立转交。缺工具交接时原固定文本和候选证据保留，不用最近调用、唯一候选或时序升级为发送目标。

这是原规则已配置的自动反馈，不要求前端在线或具有聊天查看权限；规则编辑和内容查看仍使用各自的现行鉴权。

本模块限定规则文本、业务路由及受控TLS出口上的窄修改能力。MCP管道、通用聊天编辑、自动重试、风险推定和重新授权不在此模块。当前工具到进程的明确执行上下文桥仍缺失；缺口见[模块待定记录](../../archive/unresolved-module-contracts.md#固定规则拒绝反馈的供给缺口)。不能按相同命令、父子PID、进程名或时间接近拼出关联。
