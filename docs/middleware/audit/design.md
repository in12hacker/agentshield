# Agent因果审计与Ask上下文

本页确定产品模型；[架构](architecture.md)定义职责，[技术契约](technical.md)定义业务结构。审计窗口从中间层业务数据库查询，是否取得取决于真实桥与原记录；现有底层事实和条件反馈按原契约工作。

## 发起者与审计链

发起者是Agent的真实进程实例。大模型响应提供工具请求；tool_call中的命令行是请求数据；实际执行者可以是Agent本身或它启动的进程。不得把LLM、Agent、工具请求、OS进程和原操作视作同一实体。

产品审计链为：Agent → 本次模型请求／响应 → tool_call → 实际操作 → 系统执行回执；Agent随后上报的工具结果另以原协议引用连接。系统回执与Agent上报结果都展示，不能互相替代。Allow只表示AS检查点放行，不能称业务执行成功；模型请求了某工具也不表示工具已经运行。

关系由原始来源证明。命令行相等是执行内容一致性的证据，不单独成为因果边；不拆词猜shell语义、不取最近时间、不把父子关系自动升级为工具归属。一个工具可以产生多次操作，一次系统操作也不能强制只配一个工具。多条明确来源冲突时展示缺口，不任取一个。

已取得的部分证据立即用于候选联系与展示：原生现场工具对象和原模型ToolCall标识相符可显示候选；跨HTTP原标识及来源相符而会话未证时，工具上报结果可候选连接。候选始终标明依据，不因唯一而确证；系统原对象交接继续单独显示确证。上行原ToolResult内容直接作为“工具上报结果”，不以NativeReturn或全桥完成作为展示条件。

Agent身份复用ProcessKey。审计根实例来自明确选择或有来源的执行绑定，不按程序名识别品牌，不把任意LLM连接建立者自动认定为其全部请求的写入者。根实例与实际actor分开保留。

## 已有部分先连接

不等整条链齐全才提供审计。原协议、问询完成和原请求明示引用各自可核就展示；缺Opening原件时仍保留本条来源明确给出的引用和缺口。不同段暂时链不上，保留断点及各段原件，不补造中间对象。

时序可作补充：实际source、线程实例、原操作返回、已保留回调顺序、原request/work和结果值共同满足已定义模式时显示补充连线。图中标明它是多条件时序匹配，不冒充ToolExecution或原对象交接证明；多个同点候选和原值冲突继续显示，不任取一个。该读结果不影响防护规则、Ask答复、trigger_call或固定拒绝提示发送权限。

## Ask最近20条的唯一含义

Ask首先展示原操作、实际命中规则、允许的选择及原期限。上下文补充与答复通道独立；补充信息没有准备好不延迟Ask，不重设期限。操作继续由原驱动保管，等待前端展示不改变同步裁决语义。

正式 WS 使用这些已有字段完成问询。精确归因取底层显式证据；无工具桥时仍提供原事件和结果，按原 ContextGap 表达上下文缺失。[接口范围](../technical.md#5-交付顺序与来源缺口)

“触发该Ask的大模型上下文最近20条”定义为：取得明确tool_execution关系后，定位原tool_call所在的模型交换；以该交换的原请求上下文顺序，加上本次模型响应中的消息，取末尾最多20个逻辑消息。它不是同容器、同进程或全局最近20条。

一条消息内多个tool_call仍算一条消息；SSE片段、Delta及同消息的新revision不另计条数。原请求历史只在这个确定交换内计一次；原协议本来重复的相同消息仍保留，不按文本去重。系统／开发者／用户／工具角色保持原值；原值采集按既有聊天权限提供。

上下文少于20条时展示实际条数。没有明确工具桥、原记录未取得、原源有缺口或多个目标冲突时，明确说明未取得对应上下文；不得拿另一会话补足20条。独立的Agent活动浏览可以展示该主体观察到的消息。Ask也可返回后端已核候选交换的原消息；全部候选窗口共享确认窗口之后剩余的条数预算，不各自再附20条。候选、比较条件及多候选歧义独立展示，不冒充本Ask已确认的触发上下文；唯一预算与读取规则见[技术契约](technical.md#调用方消费边界)。

## 为什么触发

界面解释取原EventData、RuleHit、规则版本及真实匹配字段。大模型上下文帮助用户审阅意图，不能代替规则匹配原因，也不生成风险评分或新的放行判断。命令核对结果与因果关系分别标识。Ask结束只取原OperationResult，工具结果、窗口关闭或JSON发送成功都不能代替原执行回执。

未知Agent无需改源码、插件或启动参数。现有系统对象／协议事实不足以证明工具桥时保留缺口；本需求不授权恢复预加载或推定关联。

## 完整消费交互

活动详情和原Ask上下文使用同一候选比较表单。用户明确选择原进程、原父进程或原线程身份条件，并填写回看时长；没有默认时长。时长界面使用秒，可精确填写到九位小数，提交时无损转成原lookback_ns；0保留“同一时间值”的原语义。

字段映射按原事件选择文件路径、执行目标／argv项或网络地址和端口。每个参数值明确选择“整个原值”或“JSON Pointer字段”；空Pointer只由“整个原值”选择产生，未填写的字段不冒作该选择。界面只提交原AttributionRequest，不解析命令或猜Agent参数名。

比较结果显示原查询条件、所需进程／线程、事件时间和目标、每个候选及实际比较结果；单个候选也标为候选。下一页沿原消息游标和同一条件读取，改变条件从第一页开始。原HTTP交换入口使用现有聊天工作台，按钮只承诺打开该交换，不冒称已定位具体工具行。

原Ask始终可先展示和答复，候选查询不延长原期限。完整聊天窗口在现有详情内展开：按后端原消息引用及顺序显示至多20条原消息，保留原角色、工具项、空值、修订和源缺口。确认窗口与候选窗口分别标注；没有工具交接证据时不把候选聊天称为触发原因。用户从Ask主动打开聊天工作台时只收起展示，保留返回入口与原期限倒计时；原询问继续由原答复能力保管。新的原询问仍按原路由显示，不沿用上一项的收起状态。
