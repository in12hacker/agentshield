# Agent 调用图谱产品设计

本模块Group负责监控Agent之间有真实证据的委派、调用和响应关系，并在有来源时展示原始输入与任务完成边界。每个Agent内部的模型对话、工具调用、驱动操作和执行回执归[因果审计](../audit/design.md)，Group引用其视图作为节点明细，不另建一套因果拼接逻辑。前端展示图谱，中间层组合事实，底层提供真实数据。

一般应用 Session 目录与聊天组织归[业务日志](../business-log/design.md#应用会话与原生聊天)。公开 Gateway 是两个业务共用的原协议来源；Group 只消费委派接纳、子任务终态和父公开回投的投影，不承担所有会话或聊天的解析、管理和存储接口。

启用指定回环端口观察后，驱动持续提供原 TCP 字节及进程归属。中间层从原请求、回执和现有模型记录复算委派。具备聊天内容权限的用户可以通过正式 WS 分页查看跨 Agent 调用、任务终态和模型交换。来源不完整时展示已证实部分及具体缺口。采集无需修改 Agent。

单个 Agent 的行为链明细由因果审计提供。Group 的跨 Agent 连线需要能定位两端调用方及原委派、调用或响应的证据。原版 OpenClaw 的进程内委派可以从已采集的模型请求中展示接纳回执候选，子任务终态和父回投分别按实际证据呈现。[内部行为链契约](../audit/technical.md#原驱动事件为锚的行为链)

图谱按有证据的关系连接节点。协议中的 `role=user` 只说明该条消息的协议角色，不能直接标成用户最初输入；一次模型响应结束只说明该响应结束，不能标成 Agent 已完成任务。未获取原始输入、Agent 调用标识或任务完成来源时，展示相应缺口，不用时间接近、进程亲缘、命令相同或唯一候选补边。

图谱可以不完整。未采到原生请求的工具仍显示已有原事实，候选与确认关系分别保留。用户能区分一次工具调用和它触发的多个模型交换。自动采集与其他 Agent 协议的覆盖取决于各自可核验的原始交接。

架构见[模块边界](architecture.md)，接口与数据复用见[技术约定](technical.md)。

## 子任务与父回投的原观察

用户需要持续看到已接纳子任务的原终态和父会话收到的结果来源。采集只旁路读取已存在的协议流，不能主动驱动Agent发布证据。界面区分子任务报告终态、父announce公开结果和未取得的耐久投递确认；任何一个阶段缺原件仍保留任务与对应缺口，不按时间/文本或单候选填空。

采样通道有缺口时仍保存能逐项核实的原连接事实，不把无关流的缺失变成其他任务的缺失。真正缺字节或执行归属不足仍显示缺口；新握手不以“必须先看到旧终态”为接纳条件，也不把新握手当作旧socket已结束的证明。
