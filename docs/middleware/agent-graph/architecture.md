# Agent 调用图谱架构

模块归中间层，负责 Agent 之间的只读调用关系。单个 Agent 内部的事件、工具与模型对话连线归因果审计。Group 复用既有原事实引用和业务数据库。本地 `as-agent-graph` 同时提供运行／回调明细，以及已核验 A2A 原件的跨 Agent 关系。后者只读原业务库快照，协议和 span 匹配归 Group，SQLite 字段查询归业务日志。

本地分析沿原生报告 → 字段与出处校验 → 只读视图。入口持有每个报告的输入字符串。计算阶段解析所需标识和时间，原参数、回执与原回调保留为对输入的借用。输出以回调序号及报告内原行号引用证据。每份回调输出一次，工具下挂引用列表。分析结束后释放内存，无数据库写入或后台任务。

原生报告中的来源域由启动实例、原进程和进程起点限定。每个来源独立计算，重复来源作为输入错误报告。原版 OpenClaw 的结构化工具回执、运行登记和父回投也可在同一已验明 Gateway 实例下只读核对。原生分析结果在命令输出边界结束。正式业务查询继续使用业务日志、审计和中间层协议中的现行事实引用。

驱动通过原事件通道发送所配置回环端口的 TCP 原包及实际收发区间。中间层 Group 只解析已取得的连接证据，持续写入同一业务 SQLite。离线分析和正式查询共用原追踪关联规则。WS 复用现行业务读封套、内容授权及写前检查，接收分页条件。模型结束、进程退出、工具完成和 Gateway 终态各自保持原义。

OpenClaw 接纳回执候选复用现有 Flow 原模型请求。Group 解释其中的原工具输出，业务日志在保存该请求的同一事务写入事实引用和字段位置。正式 Group 查询按同一游标读取两类证据。Gateway公开消息沿下文已核原TCP/WS来源进入同一Group消费者；Agent私有内存和运行登记不属于正式来源。

产品范围见[设计](design.md)，来源与字段边界见[技术约定](technical.md)。

## 公开 WS 来源的接入边界

公开Gateway WS被动解析复用原Group连接/字节所有权与唯一消费者，只在HTTP升级后切换同一连接的协议状态。配置模块只验证与下发明确端口，驱动不识别Agent品牌或JSON业务字段。Group私有WS分帧器不拥有另一份TCP缓存、线程或消息总线。

原业务日志保存实际收到的协议单元与来源，终态/父公开回投只索引原件字段及引用；查询由既有GroupDelegations组合。公共 Gateway 解码归[中间层窄适配](../technical.md#nativegateway-共用来源与解析入口)，Group 纯投影只借用其已解析文档；Session／聊天的纯投影与入库组合归[业务日志](../business-log/architecture.md#session聊天的纯业务子模块)。Group 不读取 Session 私有表或调用其内部解析，也不反过来承接所有会话业务。不在前端重新做跨方向归因，不把单个匹配候选推成因果。与运行登记复算相比，公开发布、子运行终态、耐久投递与实际执行效果分别保持原义。[来源和层次](technical.md#公开-gateway-旁路来源)

采样来源寿命与TCP socket寿命分别处理：前者改变退役原来源上下文；同来源通道缺口保留诊断，已核双socket的Gateway仍按原字节和实际I/O核验。socket原身份只在当前连接上下文与业务库单一事实表保管，不另设全局socket缓存；字段及失效边界直接引用技术契约。
