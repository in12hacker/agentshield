# 脚本化冒烟中间层

目的：用可重复执行的脚本操作当前AS核心MVP，替代人工界面完成普通控制、规则管理、问询答复和聊天观察。MCP明确排除。脚本是中间层客户端，不是新的规则／凭证执行者，也不能绕过底层鉴权或直接修改自保文件。

脚本启动自己拥有的服务及受控探针，产生真实文件、进程和网络操作；通过正式接口配置策略，核对原操作返回值、实际字节／文件副作用及真实退出。允许／拒绝不能仅根据一条日志或helper退出0判断。

策略采用真实资源范围：数据目录前缀、执行目录前缀和回环网段，不按探针PID／来源程序筛选。文件场景由原生程序及独立Python程序执行同一策略；场景之间通过正式接口替换策略，不增加测试专用放行规则。空普通规则仍用于出口初始化和退出，暴露默认路径问题。凭证精确进程绑定保留安全语义，与扩大观察范围分别处理。

问询先注册真实可答复渠道，读取原Ask再按场景选择Allow／Deny，保留原身份和期限；测试超时和断开时不延长等待。没有渠道时检查快速链实际结果，不制造询问命中。

普通聊天输出积压不能撤销这个已注册渠道。聊天先存原业务库，前端按需逐条读取；慢读时原Ask仍按期限收尾，之后的Ask继续有效。只有实际连接终止或明确撤权才退渠道，不能把队列容量解释成用户离线，也不能用额外阻止规则掩盖这一状态错误。

LLM场景由独立受控HTTPS客户端／provider提供测试材料，经当前AS出口使用phantom；脚本通过私有端口导入／轮换／撤销，并观察真实原始记录与聊天投影。Flow观察范围为所有受保护对象，凭证授权仍绑定实际进程生命期。该场景没有外部模型调用；真实OpenClaw另由原指定聊天负责准备及验收，不修改其源码。工具原生ID只作协议观察，不伪造其系统操作因果关系。

结果按各入口实际report逐项保存已执行的PASS／FAIL及NOT_IMPLEMENTED等原状态，未执行和未证明单独保留，不能因无结果改称产品失败。业务数据库和底层安全日志已有持久化实现，各自按实际记录核对。MCP 暂缓。正式 WS 与本地 JSONL 按各自实际传输验证。[问询验收](../../evidence/middleware-websocket.md)

服务进程由脚本持有。授权RequestStop只返回Accepted，由宿主调用唯一真实退役；脚本不追加SIGTERM，实际wait并核当前实例完成记录。外部SIGTERM／SIGINT仍走同一退役流程，Root代理不属于停止目标。报告不含真实key／phantom值，已有报告和原始失败不覆盖。

## 脚本化前端

脚本化前端通过正式回环 WebSocket 执行用户流程。首版覆盖防护管理和真实权限、Ask／答复／原操作结果、聊天订阅／断线续读／历史和活动联查。文件操作以原返回和实际效果为准，聊天沿原提交游标对账，活动关系按原引用核验。底层与驱动联调继续使用已有 Unix 冒烟入口。受控 HTTPS 夹具用于重复回归，真实 OpenClaw 场景沿指定验收聊天执行。
