# 中间层业务日志与数据库

业务日志拥有聊天与应用 Session 的业务组织、结构化入库和查询。业务库保存已经采集的模型请求／响应、公开 Gateway 原会话与聊天、工具请求与结果、原始证据、明确关系及真实Ask业务数据。底层日志只负责安全审计，两者不互相冒充。结构与接线见[架构](architecture.md)，存储和接口见[技术](technical.md)。

聊天采集和业务入库不依赖前端连接。数据消费后释放，历史查询读SQLite；不在Flow或中间层保留聊天历史、replay、snapshot缓存。队列只保实际尚未出队的容器，SQL事务和一次查询返回值属于在处理工作，不是历史缓存。

原始协议、应用上报的工具结果、系统真实操作回执分开保存。内容相等只说明内容相等；不能据PID、名称、时间、相同命令或仅剩一个候选生成工具执行关系。没有通用执行桥或Agent根绑定时保留明确Gap。Agent调用图谱复用原事实引用，不把第一条user消息或finish_reason当作任务开始／完成。

Ask展示、原期限和答复独立于数据库。SQL繁忙或失败不改变HIPS决定，不要求先写库才能展示Ask。业务写入的Stored只表示该事务已提交；不表示前端收到、原操作完成或模型遵从。SQLite提交失败明确报告，不返回空成功，也不建立无界RAM待写队列；已接纳工作仍保管到实际返回。

Ask的确认窗口来自已证明trigger_call的同一exchange；候选窗口使用后端明确给出的候选交换并单独标识。全部窗口共享最多20条的预算，确认窗口优先保留原冻结引用；revision和Delta不增加逻辑消息数量。只读已入库原事实，少于20条如实返回；缺桥不补全局最近聊天。具体顺序、修订和条数由[审计窗口契约](../audit/technical.md#调用方消费边界)定义。

固定规则反馈复用[已有条件接口](../execution-feedback/technical.md)。业务库保管原结果、输入来源、绑定与真实阶段，Flow只持已经发起的在途写事务。原结果保存与反馈是否具备发送证据分别认定，不因缺反馈关系丢弃已取得的真实拒绝，也不建立聊天快照。

## 应用会话与原生聊天

用户按真实会话查看已观察的连续聊天，并能区分不同会话、会话重置和来源缺失。原生来源优先使用应用明确给出的 Session ID；会话 key 是另外保存的原引用，可能为别名，同值不自动代表同一个会话实例。Agent 标识只取原协议，不从 key 的拼写、进程名或用户提示猜测。

目录区分模型 HTTP 选定字段的分组和公开 Gateway 的真实 Session。前者表示原请求明确携带同一字段，后者表示应用明确发布的会话实例；两者不因文本相等而合并。原生会话的聊天可以独立显示；未证实的模型交换归属继续显示未关联。同一已核 Gateway 发行域发布的同一真实会话，在观察连接重连或多个观察者在场时保持一条会话，各原始观察分别可追溯。实际发行域未核或身份冲突时保留原件与缺口，不全局只按 ID 字符串合并，也不把观察连接当应用会话。

原会话创建请求携带的首问也是聊天输入，按原方法和字段保留，并沿其真实成功回执关联到创建的会话与运行。直接文字输入与带角色／内容字段的消息对象各按原形状展示，空文字不丢；未配对或失败的提交仍可读，并区分协议输入角色、应用接纳与实际执行结果。协议 User 角色不表示已证明真实人类身份。

聊天正文、角色、原字段类型、空值和实际修订保持原值。同一原消息的修订在该消息下展示；只有流观察而没有消息身份时明确称为原聊天观察，不按事件数量宣称产生了同样数量的新消息。部分会话事实或聊天已取得时照常保存，缺失、冲突和未配对分别说明。

应用公开历史窗口是会话聊天的原来源，完整窗口、增量和窗口重置各保原义。原生聊天按已证明的会话消息顺序或同一原窗口数组顺序展示；迟到的旧历史不当新消息排到最新对话后。顺序不足时区分原窗口和未定序观察，不称已还原完整对话。读取途中原成员或位置依据改变时保留原页／原引用并说明变化，用户可重新读取同一会话，不悄悄转到其他对象。模型 HTTP 交换继续沿其原消息顺序。

AS 自有观察对话容器只表示 AS 组织所见原件的容器，不是应用 Session、Agent、任务或 provider Conversation。它是用户允许的后备设计概念，不替代已存在真实来源的解析；本设计不定义自动合并算法，也不据此生成虚拟 Session ID。

本模块只旁路消费与只读展示，不管理 Agent、创建或重置会话、不发送聊天、不主动调用 Gateway／SDK，不新增搜索或批量导出。内容读取沿同一真实连接授权。原始来源、字段和缺口见[技术契约](technical.md#session-与原生聊天业务模型)。
