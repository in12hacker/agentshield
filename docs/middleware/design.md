# 中间层产品设计

正式回环 WS 支持本机问询、聊天工作台和防护管理。当前只迭代AS自身实现及自有测试环境，第三方模型和Agent只作为实际工作流背景，不要求其整改，也不把减少AS额外处理宣称为加速Agent。[架构](architecture.md)定义模块边界，[技术契约](technical.md)定义接口、数据结构和授权。

## 产品目的

前端和IM通过同一WS服务查看保护状态、配置规则、接收问询和提交决定，查看LLM聊天、工具调用及实际系统行为。中间层提供这些业务操作和可核对的上下文，客户端无需访问驱动、文件、数据库或底层模块实现。

驱动采集真实内核事实并执行原操作检查；底层拥有统一事实、规则、配置、凭证、原操作和真实结果；中间层组合业务视图及有依据的关系；前端／IM展示信息和接收用户输入。旧项目只参考业务目的，其技术架构、接口、结构及存储方案不沿用。

## 真实业务流程

- **查看保护**：展示实际驱动状态、采用的规则／配置版本、流量来源状态和明确缺口。配置为true、WS在线或某次命令成功，都不能替代当前实际保护状态。
- **管理防护**：查看并修改进程／文件／网络的Driver、记住、普通快速和询问规则；配置与临时开关使用所属底层接口。界面区分保存、采用、失败及已发生的事实，不把发出命令显示成生效。
- **处理问询**：尽快转发底层原Ask，展示实际程序、操作、目标、规则和可用上下文；答复保留原身份与选择集合，最终状态取底层实际结果。窗口关闭、倒计时结束或消息发送成功不是允许／拒绝。
- **审计活动**：按底层明确供给的进程／容器实例查看操作、聊天和工具信息；原始数据与业务关系分开。没有可靠会话边界时展示本次请求携带的上下文，不称完整任务或原始会话。
- **追溯依据**：从规则命中或实际操作结果定位原事件、相关进程、协议记录与消息；没有原生关联证据的边明确缺失，不用最近消息、PID、名称或时间补链。
- **管理凭证**：经私有管理端口导入／替换、签发／撤销phantom和导出公有CA。真实秘密及一次返回的phantom不进入普通事件、审计视图或广播。

## LLM 聊天工作台

聊天工作台展示两类原来源：模型 HTTP 交换中的消息，以及旁路取得的公开 Gateway 原生会话聊天。模型消息沿原交换读取；原生聊天沿其已核协议引用读取。应用真实 Session ID 优先作为原生会话身份，会话 key／别名、运行和 Agent 标识各自展示，不互相替代。Session、provider Conversation、一次 HTTP 交换和 AS 的观察引用分别保持原义。[业务日志产品语义](business-log/design.md#应用会话与原生聊天)

没有证据把模型 HTTP 交换绑定到原生 Session 时，两类原件各自可读，原生聊天不等待模型交换归组。缺少 Session 的模型消息仍按原交换展示；来源缺口不阻止原 Ask 或普通防护。客户端从原模型消息或工具项打开已有活动证据，不从聊天内容推定执行关系。保护概览同时提供 Driver 和 Flow 的独立真实状态。[接口与分页](technical.md#llm-聊天工作台)

## 规则配置的拒绝反馈

规则可配置固定拒绝提示词，用于减少模型收到操作失败后重复尝试造成的token消耗。文本由规则作者填写，不调用模型生成、不按事件改写。字段唯一语义见[规则契约](../backend/rules/technical.md#固定拒绝提示)。

规则模块拥有文本的校验、持久化及原命中版本；中间层的执行反馈子模块处理实际拒绝与对应调用的路由，同时适用于直接拒绝和Ask最终拒绝，不要求必须弹过窗。它借用活动视图的明确关联证据，通过底层Flow窄接口将原文随对应工具结果回传LLM；驱动只提供真实裁决，不存储或拼接提示词。底层协议修改、原内容与实际提交的记录仍归Flow。具体目的见[执行反馈产品设计](execution-feedback/design.md)。

只在实际拒绝、文本非空且目标调用有明确关联时反馈。没有关联时不按PID、时间或命令相似度选另一条调用；发送提示不改变原拒绝、不等于模型已采纳，也不保证停止重试。规则字段、原结果元数据、消费者及限定Flow写入已经实现；通用OpenClaw执行桥仍缺，未有明确关系时不注入。

## HIPS语义

风险结论来自真实字段对明确规则的匹配，展示原RuleHit和动作。Driver显式Allow可过滤已知常规活动；本操作没有有效规则候选时默认放行不制造命中，也不证明行为安全。ToUser只是移交，不表示危险。中间层不设风险评分、可信进程猜测或第二套裁决规则。

一条规则只属于一种类别，按既定组号／规则号和阶段顺序执行。规则、字段供给或执行能力不足时按底层实际错误报告，不能删条件、缩减终止范围或静默降级。业务关系按原证据种类展示，候选联系及明确模式命中保留各自依据，不输出概率风险评分，也不把候选标成确定因果。

## 范围

问询闭环包括首次鉴权、声明可答复、接收原 Ask、提交原选择和取得原执行结果。文件问询在原写打开时按既有 Open 规则执行。具备 ManageService 权限的客户端可在安全日志中分页读取已配置目录的写关闭事实。已有共享映射新增写权限目前只做自保检查。[文件问询](../drivers/linux/hooks.md#写打开与写关闭) · [写关闭审计](../backend/security-log/technical.md#写关闭审计)

首次鉴权建立本连接的服务端授权，客户端随后明确声明可接收并答复问询。重连建立新连接，原连接丢失时由底层按原规则处理在途 Ask。前端关闭展示窗口和成功发送答案各自只表示对应交互事实，最终裁决以原执行结果为准。

正式回环 WS 支持首次鉴权、原问询闭环、聊天工作台及防护管理。普通组与 Remembered 组通过同一规则管理入口，配置、临时控制和凭证操作返回各自实际结果。运行审计可查询原进程树、容器归属和规则命中，具备管理权限的连接可分页读取已提交安全日志。默认 rootful Docker 私有网络的实例归属已通过真实验收，其他环境按实际供给展示。回答时「记住」和精确工具执行归属仍待接通。[接入顺序与依赖](technical.md#5-交付顺序与来源缺口)

普通日志按需查询，不默认全量推送。LLM聊天和原Ask主动上行。聊天入库与原Ask／答复独立推进，不以前端正文写出为前置；单socket已开始帧及控制输出仍有真实背压，不承诺硬实时送达，也不能据此触发自动放行；没有有效交互渠道时按既定底层无渠道语义处理。

Agent发起者、证据关系、Ask最近20条及底层内存／中间层JSON边界统一遵守[审计分层](audit/architecture.md)，业务字段仅在[技术模型](audit/technical.md)维护，不另行定义。

聊天、工具、因果关系与交互业务数据由[中间层业务日志](business-log/design.md)结构化存储。消费完的内存事件释放，历史按数据库查询。[Agent 调用图谱](agent-graph/design.md)从已核验的本机 A2A 原件建立关系，通过现有授权 WS 查询。
