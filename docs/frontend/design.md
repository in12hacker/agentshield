# Dashboard 产品设计

[架构](architecture.md) · [技术与控件验证](technical.md)

## 目的与范围

浏览器展示已经授权的防护事实，接纳用户明确的管理输入和原 Ask 答复。唯一页面注册表为 [navigation.ts](../../ui/dashboard/src/global/navigation.ts)，包含 overview、processes、rules、activity、group、chat、settings、egress 八页。overview 的范围与回执锚点不是第九页。前端不决定安全风险，不补 Agent 身份，不推定内核效果。

## 工作区

- overview：分别读驱动和 Flow 状态；模块卡、详情链接定位原回执，进程链接进入原进程列表。失败、接受、完成和缺失分别展示。
- processes：分页查看进程寿命与容器实例；本页分组、详情和原件展开只消费当前页。生命周期、页大小、完整 workload 筛选和下一页使用正式进程查询。Group 的完整 ProcessKey 直达使用 Get，不用裸 PID 替代。
- rules：查看三类规则、执行位置及组/规则详情；管理者明确创建、编辑、启停和删除。作者可选操作仅包含当前可用于规则的进程Execute、现行文件控制操作（含Driver独立Mount规则）及网络Connect/Send，已知协议事件仍完整读取和展示。容器namespace为可选作者输入，留空仅匹配未提供命名空间的实例，不表示通配；非空输入原样提交。通用事实中的真实空字符串继续保真显示，不能将事实域空值规则套用到作者域。编辑、预览、返回、取消是本地草稿，最终确认才提交带原版本的 RuleChange，复杂组合由后端最终编译。保存回执不等于驱动采用。条件、参数、容器、动作输入复用现有组件。
- activity：授权读取安全日志，选择原行，按原 EventKey 显式读取证据；允许取消等候、检查原件及下载当前选择。缺证据保留缺口，展开不能制造确定关系。
- group：查看 A2A 事实及 OpenClaw 接纳候选；节点详情仅是观察到的进程。进程详情跳转和 receipt 原 HTTP 交换跳转由用户明确操作，不扫描历史寻找替代对象。
- chat：分页浏览原交换/消息；显式展开应用 Session 目录才查询目录。会话筛选、全部交换、正文读取复用原身份与独立内容授权；不推定 Agent 身份或完成。
- settings：读取固定源配置、编辑启动默认值或完整 JSON、预览改变段、确认保存/重载；临时开关单独确认、单独显示运行回执。修改接入权限需明确勾选确认。
- egress：复用同一配置，展示绑定/路由和运行模式；首次设置表单从预置Flow范围借用实际进程／容器身份和现有路由，使用实际导入回执的SecretRef建立绑定，不要求用户手填ID数组或JSON；公有 CA 读取/下载，生成 CA、导入/替换秘密、签发/撤销 phantom 都沿 private 专属回执。一次值仅在当前授权生命周期展示、复制和关闭。

## 全局控件与 Ask

首次鉴权的密码输入、连接/取消、语言及连接详情分别用于提交客户端证明、结束未完成连接、本地语言偏好和查看非敏感端点。锁定释放当前连接；重连必须重新输入。导航、跳过导航、窄屏菜单、主题和语言是本地行为；header 刷新只读概况。导航聚焦目的标题，展开详情聚焦详情标题，返回恢复触发控件。异步回执不能把页面滚回顶端。

Ask 在所有页面上覆盖显示。原 choices、timeout、期限和双重身份来自原问询。展开意图/因果链和长文本是本地操作；上下文读取可取消，不能延长期限。允许/拒绝/原终止选择只发送一次，按钮发送后禁用；等待中的原问询不通过通用关闭或 Escape 取消。显式查看原交换时可只收起展示，并保留原期限和返回入口；实际完成后可关闭或沿原事件查看活动证据。[候选与完整窗口交互](../middleware/audit/design.md#完整消费交互)

## 可重复验收边界

浏览器验收用真实 Vite 应用和 Playwright 路由的契约形状 WS 供给，检查出站参数、供给回执和用户可见结果。这证明浏览器消费契约，不证明真实服务、鉴权实现、驱动加载或内核防护。测试结构、逐控件用途和未执行记录见[技术](technical.md)。测试报告才描述具体批次结果；设计中不把计划写为通过。
