# 主模块消息封装产品设计

公共引用：[MainContext公共上下文](../../../contracts/main-context.md)、[模块唯一职责](../../../architecture.md)。公共定义以链接目标为准，本页不另定义一份。

消息封装属于主模块，包含与中间层通信和与驱动通信的两个端口。分工见[架构](architecture.md)，上层数据见[技术契约](technical.md)，驱动数据见[驱动通信](../../../contracts/driver-communication/technical.md)。

中间层转换前端、IM或其他展示形式。底层上行真实问询、原操作结果和驱动状态；下行接收用户选择、配置／规则管理、临时开关、查询及服务控制。两端不互相暴露原生句柄、任意文件路径或未鉴权入口。

配置持久内容及文件自保规则由配置模块读取和真实写入，普通规则由规则模块读取和真实写入。中间层只提交带版本的内容，底层实际执行自保范围内的修改，再报告保存和采用结果。

临时开关从中间层下发，经主模块授权／转换后交驱动，驱动实际应用并上报状态，底层转发中间层。临时关闭不修改持久配置，手动恢复或AS／驱动完整重新初始化后采用默认；普通重载不恢复。暂停进程防护不关闭文件／网络，暂停普通类别不关闭自保。

主模块不以收到、入队或发送完成宣布生效。查询读取真实状态；断线只报告连接不可用，不猜驱动已关闭或用配置默认值填补。状态版本防止旧回执覆盖新上报。

原操作Ask、用户答复和实际结果各有原身份；不增加“问询结束／撤销窗口”命令。没有前端时只走快速规则；已经等待后渠道全断按原规则超时动作收尾。中间层不是驱动控制者。

普通日志由日志模块按需查询，不因为同一消息封装就全部主动推给中间层。LLM聊天由Flow主动提供原始内容的开始／增量／终态和缺口，前端按同一消息ID更新，不能将局部记录称为全会话。订阅权限、回放与未来历史查询只按[消息契约](technical.md#flow-输出及内容授权)，未接数据库明确不可用。

当前下行命令不包含软件包更新；安装与分发不由主模块消息封装补实现，也不提供任意shell。现行管理命令只有完成必需保存及应用才整体成功；失败附真实版本与原因，不声称自动回滚或假完成。
