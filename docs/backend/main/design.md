# 主模块产品设计

产品目标是让命中询问规则的原操作等待用户决定，同时让其他操作的快速允许／阻止、消息和管理命令继续工作。主模块负责装配、调度与启停；规则、驱动、事实查询和日志各自内聚。

## 处理方式

驱动保管原操作。用户态有进程、文件、网络三个回调接口，按统一事件头选择相应规则库，快速补充已有内存事实，先匹配记住规则，再匹配普通快速规则。它们是接口，不要求每类一个线程。驱动级规则优先于用户态规则，完整优先级见[规则设计](../rules/design.md)。

有可用前端／IM且未得到快速决定的受控请求进入主循环队列。主循环补充慢事实、调用对应询问池，并一次处理一个人工问询：当前问询取得合法答复、按规则超时收尾或原请求终止后，才处理下一项。用户不面对同时弹出的多个问询，也不因一次回答授权其他排队操作。

这里“同步等待”指原操作在决定之前不能产生受保护效果；服务端以异步等待保持消息、时钟和停止处理可运行。等待发生在主循环，独立于驱动事件接收／快速回调。消息线程持续接收回答、查询和控制命令，处理日志分发；不能让负责接收回答的线程一起停住。

## 行为约定

- 仅命中规则才产生对应HIPS动作；快速允许／拒绝和用户记住规则不弹窗。已启用的匹配阶段明确未命中时不拦截；未检查的询问池不宣称已匹配。
- 询问期间必须控制同一个原操作，不能先放行再弹窗，不能把事后暂停或终止当成事前阻止。
- 无交互渠道时，直接规则正常执行；仅匹配驱动、记住和普通快速规则；不进入慢查询、不匹配询问池、不生成询问命中或询问规则日志。快速规则明确未命中时不拦截；快速规则所需事实无法确认时报告来源不可用，不推定允许。已经等待后全部渠道断开，立即执行原规则的超时动作。
- 排队占用原请求有效期；展示、日志、重连及补充事实都不自动延长。单问询不能代替有界队列；来源隔离的未明确机制先存档，不当当前交付门槛。
- 驱动／原请求失效与“没有前端”是不同情况，不能套用无前端语义静默允许。
- 事件缺失字段留空，只补缺失值；不凭PID、名称或当前容器状态猜原事实。
- 配置、规则和必需驱动能力及通信鉴权通过后才启动业务。驱动不可用时停止启动，不以观察模式冒充保护。
- 有序退出停止接纳，收尾每个原请求并等待实际执行与线程退出。管理端使用RequestStop请求当前宿主接管停止，Accepted只证明一次性端口接纳，不称Completed或Exited；实际退出由原父进程wait或服务管理器确认。没有宿主监听者、监听者已掉或端口已消费时明确不接纳。

## 驱动与功能边界

以LSM为核心的执行方案见[驱动产品设计](../../drivers/design.md)。允许为明确缺口使用其他成熟技术，但一个原操作只有一个负责裁决的执行点；主模块不叠加第二套规则或问询系统。MCP／LLM识别属于事实与协议模块，不塞入主循环。

主模块使用共同事件头、共同进程信息及三类差异载荷。正式模块按开发一个、接入一个推进；冒烟只能验证软件接口，不能证明真实内核阻断或人工等待已交付。

线程、队列与寿命见[架构](architecture.md)，事件与接口见[技术细节](technical.md)。

停止回执沿原 session 等待真实写出、连接结束或显式终止信号，不设置写出宽限计时。回执状态与实际退出分开认定；接口及字段只见[停止请求契约](messages/technical.md#停止请求与真实退出)。


## 模块初始化与驱动装配

主模块初始化时调用各功能模块初始化函数，再使用这些模块公开的驱动准备／应用接口完成驱动初始化。配置模块处理配置，规则模块处理校验和编译，驱动模块处理本机加载与通信；主模块负责依赖顺序、接线、确认和失败清理，不代替子模块实现功能。只有全部必需初始化成功才宣布可用。配置、规则、状态和原操作共用[一条驱动通信连接](../../contracts/driver-communication/design.md)。


主模块消息封装同时承接中间层与驱动接口。持久配置／自保规则由配置模块读写和导出，普通规则由规则模块读写和导出；临时开关及共同状态由主模块统一路由。驱动执行后上报实际状态，底层再转发中间层，不先显示期望值为成功。自保根由配置模块内部一次定位／派生，主模块只借用同一只读结果，文件修改实际发生在底层所属模块。

主模块通过[MainContext](../../contracts/main-context.md)及具体参数组合公开接口；子模块不内部查找彼此实现。功能归属见[模块边界](../../architecture.md)，未明确部分存档后在对应模块设计，不由主模块临时代做。
