# 底层安全日志架构

驱动直决与后端处理沿现有生产路径生成 `RuleLogRequest`。Main 把既有日志队列的唯一接收端交底层安全日志模块，把完成通知接收端交 `MessageModule`。日志与中间层通知各自推进，底层和中间层不互相导入实现。

日志模块持有单个 SQLite 连接。Main在实际驱动连接鉴权／控制端绑定之后、业务接纳之前打开固定文件，随后在原消息执行职责中消费唯一的SecurityLogEntry队列。普通规则与驱动写关闭事实共用该队列；配置读取和目录导出归配置模块，真实采集及原生对象寿命归驱动。日志模块只负责持久化和查询，写盘在现有Tokio阻塞池顺序完成。接纳、提交与原操作裁决各有真实完成条件。

Main 启动时从同一 owner 取得只读页端口，管理授权仍由原连接和消息端口持有。读写短暂共用原连接，写端不在等待队列时持锁。读端口以弱引用读取实际已提交值，随写入所有者退役。[分页契约](technical.md#只读分页)

停止时保留原生产者到原操作和驱动退出，随后等待日志队列 EOF。驱动先关闭新观测接纳并收尾其实际在途原件；主模块随后关闭该来源的日志生产者，消费者排空原队列并实际提交，最后关闭日志连接。写入失败显式上报并停止日志消费。完成通知继续排空，Main 退役返回日志失败。接口见[技术约定](technical.md)。
