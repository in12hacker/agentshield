# 规则模块产品设计

公共引用：[MainContext公共上下文](../../contracts/main-context.md)、[模块唯一职责](../../architecture.md)。公共定义以链接目标为准，本页不另定义一份。

规则控制原操作，界面负责展示和接收选择。用户只维护有明确顺序、作用范围与动作的规则，不需要理解内核队列或回调。模块关系见[架构](architecture.md)，动作和匹配细节见[技术文档](technical.md)。

## 1. 两级处理，三类规则

规则分为**驱动级**与**用户态级**。两级都按进程、文件、网络分类；一条规则只属于一类、一个组。共享的发起进程条件可用于文件或网络规则，不会因此把这条规则变成进程规则。

驱动级优先于用户态。驱动已允许或阻止的操作，不再进入用户态重新裁决；交给用户态的操作，先匹配记住和普通快速规则；只有可用交互渠道存在时才进入慢处理和询问规则。**记住规则是用户态最高优先级，不覆盖驱动级决定。**

驱动规则是显式第一层规则，包含可见的AS维护组及用户普通Driver组；不把普通快速规则或记住规则自动提升为驱动规则。规则编辑器显示所属级别、类别、组号、规则号及动作；用户可以预见哪条规则先起作用。

规则设置不隐藏已有字段，生效位置必须显式展示和设置。前端负责将内部标识映射为明确自然语言；内部不按显示文字推定位置或动作，不增加第二份界面规则。规则内部如何按hook和操作组织，以技术方案确认后的唯一契约为准。

## 2. 驱动采用三个动作

驱动明确分为**进程规则库、文件规则库、网络规则库**。每个库内部按编号排列规则，规则各自选择允许、阻止或移交；不把三类事件混在一张列表，也不把每类再固定拆成三个动作匹配池。

- **允许**：AS在本层结束检查，原操作继续，不等待用户。其他内核权限或安全模块仍可能拒绝它。
- **阻止**：在原执行点拒绝当前操作，不先执行再告警。
- **交用户态**：停止本次驱动规则匹配，把决定权交给用户态规则。原操作保持受控；这一步本身不等于弹窗。

同类驱动规则按组号、规则号由小到大，首条命中生效。需要例外时，把具体例外排在宽泛规则前；没有隐藏的“所有阻止总在允许前”。未命中时，仅当本类、本操作仍有启用的用户态规则候选才交用户态；没有后续候选则按未命中默认放行，不制造Allow规则或RuleHit。全部规则为空、相关组／规则停用或只配置了其他操作时，驱动不为这次普通操作采集字段或进入等待。独立自保及进程生命周期事实不因此关闭。

**匹配顺序以列表为唯一依据**：同一类别、同一处理阶段内，允许／阻止／移交混排，首条适用且条件匹配的规则决定动作。不叠加阻止优先、允许优先或范围更具体优先。驱动先于用户态，用户态记住、普通快速、询问的既定阶段顺序仍保留；文件、进程、网络各查自己的列表。

**类别、规则组、动作分别表达一件事**：类别决定检查哪个规则库；规则组用于组织同类规则并确定顺序；动作决定命中后做什么。同一个驱动规则组允许包含不同动作，组不额外设置可与规则冲突的动作。

界面可在当前类别内筛选“允许／阻止／交用户态”，便于批量查看。筛选仅改变展示，不生成三套规则副本，不改变编号与匹配优先级。修改一条规则的动作也不自动移动其组或编号。

例如，允许备份程序写指定文件、随后阻止其他程序写同一目录，需要允许例外排在阻止前；阻止编辑器删除指定文件、随后允许它删除工作目录内其他文件，需要阻止例外排在允许前。按动作规定一个固定顺序，不能同时自然表达这两类例外；按可见编号排列可以。

允许适合范围清楚、确实不需要进一步检查的高频操作；阻止适合能凭现场事实直接判断的明确禁止项；交用户态适合需要更多信息或交互的操作。不默认建立“进程可信，因此所有文件和网络行为都允许”的跨类别规则。

## AS 维护规则

维护放行使用同一规则文件、三个Driver池和既有字段，不在各hook增加“自己人”Allow。规则模块从配置已定位的真实自保根生成固定维护组，实际保存、编译、发布并在管理读取中展示；RuleVersion包含这些真实规则。普通规则仍由用户管理，不能通过提交同一维护ID但改变其动作／范围／日志来形成第二套含义。

- 进程Driver组1：源executable在自保根下的Execute，以及独立一条执行目标在根下的Execute，均Allow、log=false。两条规则分别表达源维护行为和根内程序启动，不把两个条件合成隐含OR；Create／Exit仍只是观察。
- 文件Driver组2：源executable在根下的现行文件维护操作，以及独立一条目标path在根下的Open，均静默Allow；完整维护操作集合只在[持久维护规则](technical.md#持久维护规则)定义。目标规则覆盖启动AS前先打开其程序文件的真实顺序；外部修改仍先被实际对象自保拒绝，不因此取得修改权限。
- 网络Driver组1：源executable在根下的Connect／Send静默Allow。真实维护连接在驱动结束检查，不进入AS自身的用户态等待。

这些条件是原路径字节前缀，前缀含目录分隔符，不能把/as-other匹配成/as。它们是明确的路径规则，不等于控制面身份鉴权；Driver端点／受保护对象修改仍用原真实身份与对象验证。当前String规则不能无损表达非UTF-8自保根，明确报不支持，不进行lossy转换或旧路径回退。

维护组由规则模块管理，在初始化／更新／重载同一入口规范化；省略时补齐，显式篡改维护组拒绝。清空普通规则保留维护规则。文件组1仍留给配置来源的对象自保；普通Driver文件组从3开始，进程／网络从2开始，不隐式改用户编号或保留旧冲突编号兼容。

## 3. 用户态：三类，各有两个匹配池

进程、文件、网络三个派生模块，各有快速池和询问池。

- **快速池**：先匹配该类有效记住规则，再匹配该类普通快速规则。动作是静默允许或静默阻止，不要求用户确认。
- **询问池**：有可用前端／IM且快速池未得出结果后，补充需要的信息，再匹配询问规则；命中后等待用户选择。

记住规则仍分进程、文件、网络三类，放在各自快速池的记住组内；它是规则来源，不是第三个匹配池。每段内部按组号、规则号匹配，首条命中生效。两个池均未命中则沿用当前设计的未命中放行，不伪造规则命中。

普通规则和记住规则共用同一个规则文件与管理入口。用户可读取全部规则或按唯一规则ID查询单条，再在明确选择的组内新增、修改、删除或停用规则；记住组分别属于进程、文件、网络，动作仍只允许静默允许／阻止。修改提交编辑时读取的版本，冲突后重新读取，不覆盖他人的更新。AS维护组可读，不能通过单条管理命令修改或删除；自保系统组归配置模块。

当前Answer只包含本次decision，不生成或保存记住草稿，也不自动放大本次授权。Ask内草稿、预览、实例范围确认及重复问询提示的未定设计归[既有待定消费链](../../archive/unresolved-module-contracts.md#已承诺但尚缺消费链的记住规则)，不作为普通HIPS或真实GLM运行前置。

每条规则有独立的“记录日志”开关。命中且开启时，主调度把原事件、规则编号／版本、决定原因和真实执行结果送到第三个消息线程；未开启不生成规则日志请求。询问超时和执行失败分别记录其实际原因；无交互渠道未匹配询问规则，因此不产生询问规则日志，不能写成用户已同意或已经成功阻止。日志排队和日志落盘是不同结果。

普通用户的编辑入口以“程序、操作、目标、动作、适用范围、记录日志”为主，提供来源程序路径与目标路径选择以及常见模板。编号顺序始终可见。高级条件再展开命令参数、PID／PPID、父进程、UID／GID、正则与网络范围，避免要求用户直接写表达式语言。

PID／PPID引用当前事件事实：快速回调填充后，规则读取这些值匹配，不逐事件替换全局规则内容。命令行按原argv参数及其位置匹配，展示用的拼接命令行不作为另一份可冲突的事实。进程执行、进程跟踪和跨进程内存访问应属于进程类中的不同操作组；只有对应Linux操作及其主体／目标字段具备真实数据供给后，才开放这些操作的配置。

当前可通过统一规则管理入口读取和编辑同一规则文件中的Remembered组；Ask回答内生成、确认及保存记住草稿仍未接线，归[待定消费链](../../archive/unresolved-module-contracts.md#已承诺但尚缺消费链的记住规则)。修改由已认证且有管理权限的消息会话提交给规则模块，统一保存并生效；远程／IM不直接修改文件。旧编辑版本与当前版本冲突时明确提示重新读取，避免静默覆盖他人的修改。驱动规则导致操作提前结束时，界面解释命中的驱动组／规则；不能显示成“记住规则失效”。

## 4. 容器适用范围

每条规则保存独立的“适用范围”；当前Driver只接受AllProtected，Backend快速／询问及记住规则另支持已核容器实例。字段语义为：

- **所有受保护对象**：包含宿主机与容器中的受保护对象，也包含以后新纳入保护的对象；不会因此把尚未纳入保护的对象自动接管。
- **指定容器**：多选一个或多个容器实例，任一所选实例匹配即可。仍是一条规则，不按容器复制规则；空选择不能保存，也不代表所有。

范围判断的是**发起这次操作的进程所属容器**。容器A内进程访问共享文件，按A判断；宿主机进程访问容器的挂载文件，仍按宿主机判断。目标文件或目标进程属于哪个容器，不改变这项范围的含义。

指定容器绑定实例身份，名称用于帮助识别。删除后创建同名容器不继承规则，需要重新选择；原容器对象停止再启动且身份未变，仍是所选对象。所选A已删除、B仍存在时，规则继续适用于B，并显示A已删除；不能自动扩大到所有对象。

范围只筛选适用规则，不增加优先级。例如，前面的所有对象阻止规则也会阻止A，后面的A专用允许不会自动覆盖；要设A为例外，应将A允许排在前面。多个容器与所有对象的规则仍混在同类、同阶段列表里按编号匹配。

手工Remembered规则显式保存当前schema支持的scope，不能以空容器列表暗指所有，也不从原Ask规则自动继承更大范围。Ask答复内的草稿确认与保存尚未接线，其未定交互仍归同一待定消费链。

## 5. 不被洪水事件淹没

先在源头按监控边界和操作种类选择需要检查的操作；直接允许／阻止尽量就地完成。网络控制以规则声明的建连等操作为单位，不把同一连接的每个数据包都变成一次弹窗。

系统和应用的常规行为可通过显式Driver Allow规则快速放行；这些规则遵循相同的类别、编号、条件和采用流程，不在代码中按名称推定可信。未被规则决定不等于危险，Allow也只表示本次AS检查允许，不证明程序没有风险。风险判断必须来自可核对的字段条件和实际命中规则，中间层不附加概率评分或按聊天／时间／进程名猜测风险。

借鉴成熟HIPS时只吸收可验证的操作／目标／主体条件、源头分流和真实执行链；实现对照及不采用的妥协见[成熟HIPS对照](../../evidence/hips-comparison.md)。不同产品的默认动作和仲裁顺序不能同时混入本规则体系。

已经完成决定的重复普通记录可以汇总命中次数、首次与最近时间，减少队列、日志和界面压力。抑制记录不改变每次操作的决定；进程生命周期等维护事实所需的事件另行保留。

每个待决定操作都有自己的原请求、截止时间和结果。第一轮不自动把多个请求合成一个可批量授权的弹窗；减少重复询问依靠明确记住的规则。不同目标、不同操作不能仅因进程相同而复用一次回答。

队列满不等于允许，不用“过载时关闭阻断”来隐藏问题。已经命中询问规则的请求，无法继续等待时采用该规则配置的超时动作；已经进入原执行的工作必须保管到真实结束。

## 6. 交互和阻止行为

没有任何交互渠道接入时，驱动规则与用户态快速规则仍生效；只匹配驱动、记住和普通快速规则，不进入慢查询、不匹配询问池、不产生询问规则命中／日志。快速规则明确未命中时不拦截；缺少快速规则判定所需事实时报告来源不可用，不跳过优先规则猜放行。已经挂起的请求随后失去全部交互渠道，立即按该规则的超时动作收尾。两者是不同的时点，不混用。

阻止动作保留三种明确配置：仅阻止、阻止并终止发起进程、阻止并终止发起进程及其原父进程。先阻断原操作，再执行指定终止；终止失败与阻断结果分别展示。驱动能否完整执行该组合由实际能力决定，不把组合规则静默缩减成仅阻止。

## 7. 成熟方案的借鉴范围

[Comodo HIPS](https://help.comodo.com/topic-72-1-766-9164-Active-HIPS-Rules.html)提供允许／阻止／询问、规则集和可调整顺序；[ESET HIPS](https://help.eset.com/eav/18/en-US/idh_hips_alert_dialog_generic.html)提供从询问保存规则及后续管理。这些是HIPS产品行为依据，闭源产品文档不能证明其驱动实现。

驱动最高、用户态记住项优先、三类各两池是AS本次明确选择，并非所有HIPS统一采用的算法。Linux授权与等待源码、网络分流及上报节流的适用边界分别列在技术文档，不能以遥测项目代替完整交互式HIPS依据。

## 与主循环和驱动的配合

用户态快速匹配由独立回调接口调用；有可用渠道时未决定请求进入主循环，逐个进行慢匹配和人工等待，只有一个活动问询。驱动负责真正保留原操作，主循环和规则模块不能从观察事件构造等待能力。原请求及失联语义见[主模块设计](../main/design.md)，执行能力见[驱动设计](../../drivers/design.md)。


文件Driver池包含配置模块导出的只读自保系统组1，文件Driver组2为同源维护放行，普通文件Driver组从3开始。自保根和固定文件名不可由普通规则编辑器改变；持久自保配置和普通规则分别由底层所属模块真实写入。命中显示origin及对应来源版本，不混淆配置投影与RuleVersion。
