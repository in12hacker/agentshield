# LLM对话采集、解析与推送

当前产品入口为受控MediateTls：选定的新连接经同一出口完成phantom认证头替换和LLM正文采集。明确支持范围、未实现范围与实际执行结果分开；[架构](architecture.md)、[公共契约](../../contracts/flow.md)和[验收证据](../../evidence/tls-egress-integration.md)各自维护。MCP继续暂缓；规则预配置固定拒绝文本已另作[产品目标](../../middleware/execution-feedback/design.md)，限定 Responses 回传按相应契约执行，通用工具执行桥未实现。

## 产品目的

AS在不修改目标源码／SDK、不要求AS管理目标启动的前提下，展示受保护应用与LLM之间实际传输的聊天。采集范围由配置明确选择；应用名称、端口443或某个IP不能单独证明正在调用LLM。

对于已支持的来源和协议，每条实际识别到的消息及其原始协议事实都主动推送给已鉴权、有该范围内容读取权限的中间层，前端由中间层展示。底层不只提供重新格式化的摘要，也不推定工具已执行。用户输入、助手输出、协议中显式携带的system／developer信息和工具内容保持原角色；请求中的历史消息标为“本次请求携带的上下文”，不能都算作用户刚发送的新消息。工具内容的解析不恢复MCP拦截任务。

流式回答是一条持续更新的消息：开始、内容增量、结束或中断使用同一消息ID。网络包、TLS调用、SSE事件不等于一条聊天。多候选回答分别展示，不能只取第一个；底层原样提供实际provider会话标识、续接ID和字段出处；跨请求分组与工具关联由中间层完成，未知时按请求展示，不按PID／时间／文本相似度猜因果。

## TLS明文与内容修改

受控出口在用户态分别与客户端、上游建立TLS；客户端实际信任AS公有CA，上游始终正常校验证书链／主机名。应用不需要修改源码／SDK，也不要求AS接管启动。配置只保存非秘密引用，真实凭证归独立所有者；每个请求核原主体、origin、method／编码path和绑定范围后替换唯一认证头。

同一正文来源同时产生原始协议观察与聊天投影，不能再采集代理自身连接重复上报。当前认证头替换与限定 Responses 固定拒绝反馈共用同一 Flow 出口；反馈必须有明确来源与授权，不动态生成文本、不增加 HIPS 匹配池。通用工具执行桥未实现。

被动ObserveTls、TLS库ABI探针及通用聊天正文编辑属于[保留设计](../../archive/flow-design/flow-contracts-before-unified-audit.md)，不作为当前能力。当前入口接收宿主和[已绑定的默认 Docker 容器](container-egress-design.md)的 IPv4／IPv6 TCP 新连接及 DNS SNI route。既有连接迁移、mTLS／ECH／QUIC／pinning 绕过不在支持范围。失败不切换为其他来源或关闭证书验证。

## 每条消息的可见性

- 完整请求／非流式响应形成完整消息；流式消息连续更新，provider终态、HTTP结束和Agent消费分别认定。后续断线保留实际缺口，不覆盖此前已取得的provider Complete。
- 丢失、截断、解析错误、中途附加或不支持的TLS／协议都主动报告对应状态。不能把空白视图解释成“没有聊天”，也不能用一个绿色开关表示全覆盖。
- 只展示线上实际可见的信息。服务端保管的历史、未公开推理、未下载媒体不补造；图片／音频／文件先保留可安全展示的类型与引用元数据，不自动访问URL或复制大块二进制。
- 本地原始协议及已取得的聊天内容、元数据按实际值保存和提供，不由AS主动脱敏、遮蔽或关键词过滤。鉴权与采集范围沿原接口，不借保真扩大数据采集。

“每条”是支持范围内的处理目标，不是对任意应用／任意网络状态无损捕获的保证。前端断线、消费者过慢或进程重启后，历史只从中间层已提交数据库查询；未提交、无库或实际丢失如实报告，不从底层内存回放或伪造历史。

普通引号、反斜线、路径、换行及看似凭证的文本都是原数据，不能替换为占位符或缺失。原始字节与结构化投影分别保真；实际未取得的内容明确缺失，不补造。旧脱敏和后续匹配器／元数据遮蔽方案已退役，历史失败仅作[反例](../../evidence/flow-redaction-readability.md)保留。

未来脱敏归业务侧，当前只列入[路线图](../../roadmap.md#未来业务侧脱敏)，不进入本地Flow或存储实现。

## 存档与修改的用户语义

聊天和业务关系由中间层[业务日志数据库](../../middleware/business-log/design.md)结构化保存。Flow 不保留历史／回放／查询快照。入队、SQL 提交、socket 发送与前端接收分别认定。

未来正文编辑只针对尚未发送的协议单元，已发送内容不能撤回，真实提交也不代表远端接受。该设计保留于归档，当前配置／消息不开放chat.edit或JSON Patch入口。

## 范围与后续验证

当前规范优先覆盖已有设计中的OpenAI Responses、Chat Completions与Anthropic Messages的HTTP JSON／SSE。兼容服务也要实际匹配对应schema，不能只看URL相似。HTTP/2必须按连接压缩状态和stream拆分；QUIC/HTTP3、WebSocket Realtime、自定义浏览器协议、其他TLS运行时在独立确认前明确不支持，不默默降级网络协议。

验证只针对实际承诺：真实TLS明文与消息对应、分片／并发不串话、异常有缺口标识、前端可恢复范围，以及受支持修改路径的真实对端结果。具体已执行范围见证据页；先运行完整正常真实业务并保留输入、输出与效果，再据实判断能力和必要的临界验证。文档、编译、本地软件测试或旧候选通过不表示新候选真实实例已经生效；性能改进只针对AS自身额外工作，不推定或承诺Agent速度。
