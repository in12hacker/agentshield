# 进程树架构

产品目的见[设计](design.md)，数据和接口唯一出处为[技术文档](technical.md)。本模块属于底层，只按参数接收设置及真实事实端口，不接收不使用的MainContext；不进入内核DriverContext，不导入配置、规则或驱动的实现。

## 内部边界

一个ProcessTree实例拥有内存状态。内部仅分三项职责，可在少量文件中实现：系统读取器读取／核对当前进程；状态维护器维护身份、两份快照、关系和命中；查询器返回只读详情和分页结果。读取器不直接发布半成品，查询器不另建可写缓存。初始化／刷新得到的结果仍交同一状态维护器采用。

主模块取得配置参数，构造进程树，将同一实例接入FastFacts和查询端口；它只调接口，不枚举/proc、不维护父子map。操作系统读取属于进程树；需要纳秒级身份等内核事实时，只调用主模块传入的窄事实查询端口。底层驱动适配实现该端口，复用原已鉴权连接，不让进程树再打开设备或注册一套驱动。

## 初始化衔接

1. 配置和规则按原顺序准备，主模块构造处于Building的进程树并接好快速事实消费者。
2. 主模块连接真实驱动，先开启基础进程观察，取得采集开始标记。观察在普通规则初始化前可用，但不宣称防护已经生效。
3. 进程树initialize在阻塞工作任务中枚举整机进程；快速线程持续消费观察。扫描结果逐批经同一维护入口合并，不阻塞接收器直到整轮扫描完毕。
4. 扫描完成后取得事实流栅栏，确认栅栏前已接纳回调处理完且无丢失，补齐待关联的父节点和受竞争影响的记录，再原子公布Ready及镜像收据。
5. 主模块通过配置／规则所属接口完成正式驱动采用；进程树和必需防护均真实就绪后才对外宣布业务就绪。失败按已经取得资源实际退出，不用空树完成初始化。

MainAssembly实际构造并保管唯一ProcessTree，同一实例承担FastFacts和查询。基础观察在Dormant／Failed也可开启，包含内核线程组；事实模式与普通控制共用已鉴权连接。观察已开启不等于普通防护已采用，整体就绪仍以真实初始化收据为准。

## 线程和临界区

- 回调／快速线程：对原事件做一次内存查找、维护与补空，然后匹配规则；创建、exec、退出处理同样在此入口。禁止/proc读取、等待驱动查询、数据库或全树遍历。
- 串行主循环：消费快速入口已经补全的事件。现有慢事实接口供后续明确的慢字段实现接入，当前进程树不重复提供同一份内存补充。
- 消息线程：处理查询、显式刷新和修复调度；详情缓存缺失时复用同一读取任务执行一次定向补取，阻塞扫描由进程树拥有的spawn_blocking任务承担，完成后短临界区合并。没有第四条常驻业务循环或按类别新建线程。

初版用一个短时读写锁保护节点及关联索引的一致修改。写锁只覆盖一次有限记录合并，不跨await、系统调用、规则匹配或消息发送。缓存查询在锁内只克隆不可变快照Arc或一页结果，序列化和遍历在锁外分批进行；大型子树导出有取消点。维护单个节点不复制整棵树，不提前引入分片锁、无锁树或MVCC版本库。

## 运行与退出

生命周期回调是实时维护主通道。cwd、参数原地修改、凭据和父进程重定向不都具有当前已接回调；相关字段因此标注观察时点，通过有合并能力的刷新修复，不能把定期扫描伪装成驱动实时捕获。稳定父关系及缓存查询使用索引，不每次沿全树找父节点。

来源断开、丢失或身份冲突使完整性标为Uncertain，仍可展示明确标注的已知记录。原事件自己的事实仍可用于快速裁决；未知的补全结果保持None，不自动放行或改动原期限。当前同一树实例只绑定一次源；断流后需要主模块完整重启并新建树重新核对，尚无热重绑定端口；失败返回原因，不无限重试。进程死亡不取消已经由其他执行者保管的原操作。

停止顺序是停止外部新查询／刷新、停止驱动新观察并处理最后标记、排空已接受的事实和查询任务、释放树状态。长期查询只持只读快照，不持树锁；取消查询不丢弃已经开始的刷新资源。主模块负责总体顺序，进程树只完成自身close。

## 当前代码边界

- `as-process-tree/src/scan.rs`：固定procfs读取、真实身份前后核对、扫描／刷新；只读，不保存配置或日志。
- `store.rs`：节点、父子索引、初始／最新视图、字段时序与有界退役队列；不执行规则动作。
- `query.rs`：只读查询和实际命中归集；不鉴权、不监听socket，不建立另一规则池。
- `model.rs`：公开只读视图与快照存储计量；`lib.rs`：实例寿命、补全、事实失效和任务保管。

共享身份／设置／查询输入位于as-types；初始化、通信授权和路由由as-main组合。移除未使用的MainContext入参；进程树不需要安装路径，也不自己读取AS配置。HashMap/BTreeSet/Arc/RwLock及现有Tokio任务保管已满足本模块管理需求，不增加注册框架、通用总线或第二份系统进程缓存。

详情补取只用节点内Pending／Completed状态和原扫描互斥锁进行并发合并，不建立第二事实缓存。Pending与完成分开，取消调用者不放弃已接纳读取；同一代失败缓存，真实exec不会被旧读取的收尾覆盖。FastFacts始终只读缓存，不执行动态/proc或驱动查询。
