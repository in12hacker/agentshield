# 进程树产品设计

本模块属于Rust底层，由主模块初始化和接入。职责与执行安排见[架构](architecture.md)，字段及接口见[技术文档](technical.md)。本页描述当前实现的产品语义。进程树已由主模块初始化，使用同一事实流、系统扫描和已鉴权查询入口；真实执行范围另见验收记录。

## 目的和范围

AS启动后先取得当前系统的完整进程清单及父子关系，之后持续消费驱动的创建、exec成功、进程组退出和其他事件中的进程事实。既有进程、AS自身、宿主及容器中的进程、内核线程组都在系统清单内；不按普通防护开关、日志选择或前端在线状态隐藏进程。线程不是独立的进程节点。

完整指覆盖宿主PID命名空间内的系统进程和初始化期间变化，不表示所有进程、所有字段在同一个CPU时刻被原子冻结。读取权限不足、字段缺失、采集中退出及回调丢失必须明确显示；不能将局部命名空间中的列表称为整机镜像。无法确认整机覆盖时初始化失败；个别属性读不到时节点仍存在，该属性保持未获取的None。

模块提供两个用途：快速规则开始前从内存补全原事件缺失的进程信息；向已授权查询方提供进程详情、父子关系、最初／最新属性、命中规则和数据状态。列表、父子和快速补全直接读内存；单进程详情仅对未取得且有真实来源的字段异步补取一次，并缓存结果及失败。浏览列表不会触发逐进程磁盘读取。

## 最初数据与最新数据

每个真实进程实例只保留初始和最新两份易变属性视图。初始是AS首次接受的真实样本，生成后不修改；对启动前已存在的进程，不能冒称这是其出生时的属性。初始没有读到的字段保持None，不用后来的值回填历史。

最新是最后一次已确认的观察，不承诺是操作系统此刻的即时值。名称、程序路径、参数、工作目录、凭据、父进程和cgroup均可能变化；每个值保留采样来源与时点。新exec成功时使旧镜像相关字段失效，不能保留旧参数配上新程序路径。失败的exec不更新已执行镜像。

创建者与实际父进程分开。父进程退出后保留原始父关系；当前父关系只按真实重定向信息更新，不能直接猜成PID 1。未知父节点作为待关联关系展示，不伪造进程。进程退出后有界保留详情和命中汇总，避免弹窗或查询一结束就找不到原对象。

## 快速补全与规则

主模块先调用进程树的FastFacts，再选择对应规则池进行Remembered／Fast匹配。所有进程、文件和网络事件都经过这个入口；驱动已经决定的事件仍用于维护事实和命中统计。无前端只跳过慢查询和Ask，不跳过快速内存补全。

补全按真实进程实例查找，只填原事件的None字段。规则上下文由“驱动本次已采到的事实＋该事件时点之前树中最近确认的信息”组成，缓存值不冒称同一次hook的原子采样。不得覆盖驱动已有值、拿相同PID的后继进程补全、使用后来的exec或凭据解释更早的事件。节点及字段未被标记失效、身份和采样时点符合时，就使用缓存补齐名称、路径、参数、父信息等；不要求每次匹配重新读系统或等慢查询。已知失效、未来值或确实未知的字段保留None，由现有NeedsFacts／Unavailable语义处理。

初始数据用于对照，不能因为最新数据未知而退回初始值作当前规则输入。慢查询补充与当前展示查询也要分清：刷新得到的新值可以更新进程树，但只有适用于原事件的值才能参与该事件的匹配。查询结果不能替代OriginalOperation授予执行或终止权限。

## 功能边界

进程树独占系统进程扫描、实例识别、内存关系、两份属性视图、补全和查询。规则模块仍负责匹配；日志模块负责持久保存；驱动负责原生事实和原操作；消息模块负责首次鉴权及远程表达。进程树不连接Docker／IM，不解析MCP，不保存完整环境变量、内存内容、文件描述符全集或未设计的hash／数据库信息。

规则命中按原进程、类别、来源版本、组／规则身份去重累计。统计只表达实际收到的命中；丢失或驱动未上报时明确不完整，不能显示成全量审计。规则log仅决定是否写日志，不改变进程基础事实维护需求。

成功读到空命令行是已取得的空值，字符串语义为""，现有argv数组保留[]，不能改成null。已取得的空值不会触发补取；来源空内容也不能被推断为原事件确有零个参数。详细来源和可用于规则补全的范围分开，保持原始数据。
