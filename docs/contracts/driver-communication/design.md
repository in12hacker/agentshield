# 主模块消息与驱动通信设计

公共引用：[MainContext公共上下文](../main-context.md)。公共定义以链接目标为准，本页不另定义一份。

初始化与归属见[架构](architecture.md)，消息和数据结构见[技术契约](technical.md)，配置字段见[配置设计](../../backend/configuration/design.md)。

## 主模块统一消息入口

主模块的消息封装有中间层接口和驱动接口。中间层提交配置／规则修改、临时开关及查询；底层鉴权后调用所属模块或转换为驱动命令；驱动返回真实结果／状态，底层再报告中间层。发送完成不代表修改成功，收到请求时不能先显示已开启或已关闭。

主模块初始化负责调用各模块初始化函数，并通过其公开接口完成驱动初始化。配置读取和写入属于配置模块，规则读取和编译属于规则模块；主模块组织顺序、接线与确认，不复制它们的实现。

进程、文件、网络共用一条已鉴权驱动连接，各自保留独立回调和匹配池。中间层不直接连接驱动，不获取驱动句柄或自保目录写权限。

## 三种内容分别负责

1. **持久配置与文件自保规则**：配置模块读取并保存；初始化时导出驱动持久配置。自保目录仅由配置模块内部按实际后端安装位置一次派生并缓存，不允许中间层修改；普通规则不会授予自保写权限。
2. **驱动匹配规则**：规则模块从固定规则文件读取、校验、编译和保存，提供进程／文件／网络三类DriverPolicyImage。不是配置模块再维护一份普通规则。
3. **临时开关与状态**：主模块消息入口统一处理。临时暂停不写配置／规则文件，直到手动恢复或AS／驱动完整重新初始化；普通重载不清除暂停。驱动执行并上报实际状态，底层转发中间层。

暂停进程防护只暂停普通进程防护，不关闭文件／网络和文件自保；暂停普通文件防护也不包含停用自保。类别关闭后仍必需的基础身份事实由其模块维持，不把“暂停防护”误称为卸载所有回调。

## 自保内修改由底层实际执行

中间层只传配置内容、规则内容或已认可的软件包标识。配置模块实际写配置，规则模块实际写规则，其他自保文件由底层所属模块执行受控修改。不存在返回一个路径让中间层自行编辑的成功流程，也不提供任意路径写文件或可转交的维护授权。

自保写许可绑定经过驱动验证的底层服务进程实例，并限定自保范围和操作；不是按进程名、裸PID或客户端声明放行。目录自保必须能覆盖实际要求的修改／删除／重命名等行为；只阻止open不能显示成完整目录自保。

## 大缓冲与跨系统

小控制和大规则镜像使用同一消息封套。大缓冲分段传输、完整校验后一次采用；发送片段之间允许插入回答、开关和状态请求。半份规则不生效，传输失败保留原有效状态。

当前Linux使用受保护字符设备；Windows的FltMgr通信端口仍为未实现的平台设计，不声明已可使用。主模块统一业务含义，薄平台适配封装系统接口。接口统一不代表各系统拦截／等待能力相同，不支持的操作明确拒绝。

协议只保留现行格式，变更时同批迁移所有生产者、消费者及文档，不建设兼容解码或后备通道。

接口通过MainContext和具体参数组合，模块边界见[统一归属](../../architecture.md)。未明确功能先存档，不让主模块交叉调用私有实现或复制一份算法。
