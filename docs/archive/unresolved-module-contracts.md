## 驱动内部尚未确定的表示与绑定

驱动与Rust底层是两个大模块，DriverContext只在驱动内部文档维护，MainContext不跨入驱动。已确定的子类职责、唯一状态提交和只读上下文见[驱动总契约](../drivers/technical.md)；以下只保留尚未决定的实现细节：

当前Linux只读快照引用、具体编码、控制者及固定自保对象绑定、原版本选取和FIFO退役已归正式契约，不继续列作未决定项。驱动转交命中与底层最终命中分别保留，真实执行仍须验证。

## 原生工具上下文的持续采集

已有系统原事实用 `EventData`，已证工具原值另用 `ToolExecutionFacts`；后者不是所有旁路来源的入场条件。当前方向是系统层原始观察与明确模式组合，具体归属见[驱动适配](../backend/driver-adapter/technical.md#原生请求持续采集与工具边界)及[业务模式](../middleware/audit/technical.md#通用操作系统模式)。

R48／R66 实验采集器使用固定 Node 24.22.1 映像位置与 V8 对象布局，入口固定为 `uv_fs_open`，只选择指定 PID 和路径，保存上限为 32 条记录。它通过独立实验 `/proc` 端点读取归档。正式持续采集需要将实际运行时绑定、同次回调采集、原请求交接和原会话退出组合起来。用户已明确保持跨语言方向，禁止固定 Node 发行版及逐 Agent 私有适配，并要求调查按语言运行时维护支持范围；尚未定义可下发的完整布局配置或新驱动消息。

原验证二进制 SHA256 为 `c8c5721679d8d1a09e9987e345d5f9a64899bb85f7a384783ba8a93e6e62348a`。已核 Node 的 `req.data` 可移除实验的包装器相对固定偏移，运行时初始化的 `nodedbg_*` 可给出 BaseObject handle 与字段数，不能从 ELF `.bss` 零值解释这些字段。缺失的全部 V8 Map／对象布局与原工具的通用语义仍未取得；原应用 `toolCall`／`assistantMessage` 名称不能移为通用选择器。具体源码及实读见[持续采集前提复核](../evidence/runtime-correlation-research.md#持续采集接入前的源码与实读复核)。

职责已明确。驱动管理原探针及原生请求生命周期，瞬时值随本次上下文释放。驱动适配负责映像／ABI核验和真实帧解码，Main 沿原消息队列交付事实，业务日志保存原值，中间层按明确协议作用域绑定。原完成需记录到业务库时，原生事实先于完成在同一队列交付。初始化失败、运行中的采集丢失及原生退出各保留实际结果。

按运行时读取元数据有成熟先例，布局解析与工具语义分别核验；这些缺失不阻塞已经有来源的系统事实。待明确的是新增现场字段的真实采集点、有效期、缺失／截断语义及沿原拥有者的交接。业务层允许时间窗口与线程、同步对象、事件顺序共同作为明确模式条件，不以裸时间接近冒充对象身份，也不因单个旧窗口方法失败否定其他系统模式。固定偏移、目标注入和逐Agent适配不作为回退路线。源码研究保留在[运行时元数据](../evidence/runtime-correlation-research.md#按语言运行时适配与布局元数据)。

数据结构处置：`ToolExecutionFacts`／`NativeToolContext` 足够承载已有工具事实，不能强装任意系统快照。新增原执行字段优先归同一 `EventData`，复用原线程／事件身份和队列；不得把HTTP EvidenceBody改成内存转储或复制一套进程字段。中间层现有 Timing 分类仅为离线时间候选，新多条件模式尚未实现；后续先定真实字段和引用，再实现所属模块，不新增评分、Agent模板或无消费者接口。

原操作系统调用寄存器与内核栈的字段、临界区和消费已落地，不再作为待定接口；唯一结构见[事件执行现场](../contracts/events.md#原操作执行现场)，代码／产物验证见[本轮证据](../evidence/execution-site-capture.md)。此处仍保留的是其他真实同步／请求交接来源及业务模式，而不是重复实现已存在的现场字段。

## Session 服务器自有消息的真实来源

归属沿现有驱动原事实、驱动适配及中间层 Gateway 来源入口；应用 Session／聊天字段解析仍归业务日志的纯业务子模块，不下沉驱动，不另建采集栈／SDK。现有源只发布 init_net 中双端 `127.0.0.1` 范围的包字节与 I/O；放宽 Group 查询条件不能补出容器服务端原件。宿主代理自己转发的字节也不能改称容器进程的 I/O。

服务端自有观测需要先由原 source owner 明确定义并真实供给：服务端完整 ProcessKey；该 socket 的真实 netns／本地端点及寿命内 cookie；自持有的服务端实际字节、方向、区间、顺序／协议边界依据与缺口；仅指向这些原件的来源引用。现行 Transfer 没有 payload、netns 或地址，不能据空缺客户端构造 GatewayConnection。具体原回调采集点、首字节／升级声明的边界及导出类型尚需所属 source owner 核实，不在此臆造字段默认、读取目标私有内存或将输入缓冲快照冒充已发送 wire。

Session 只确认该服务端自己声明的会话与聊天；对端 actor 未取得时保持未取得，不成为 Group 的跨 Agent 确认。Group 保留原更强证据。新增事实须沿原通道／原件 owner 同批迁移生产、适配、存储和消费者后才能接入；源未足时保留已有原件与明确缺口，不以此阻止普通 CoreHIPS／phantom 或基本打包。
