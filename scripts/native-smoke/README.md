# Native SDK guest smoke

“SDK” in this diagnostic means AS's own backend driver adapter. It is not an SDK installed in a target Agent and does not authorize runtime injection or preloading.

This is a disposable Linux guest diagnostic for the real SDK, current Native module and complete BPF hook set. It reports ordinary file protection only; its deliberate path-free diagnostic configuration does not prove formal AS self protection. The formal configuration/exporter is unchanged.

Build a new directory with `scripts/native-smoke/package.sh /tmp/NEW-DIRECTORY /tmp/CURRENT-NATIVE-BUILD`. Source `$HOME/.local/share/agentshield-ci/env.sh` first. `CURRENT-NATIVE-BUILD` contains `module/as_wait.ko`, `as_hooks.bpf.o` and `as-bpf-loader` built from the frozen current sources for the exact guest kernel. Use `drivers/linux/build.sh all` for those assets. The packager copies the Native assets byte for byte and builds its static GNU Rust example.

Boot the produced `initramfs.cpio.gz` with that kernel, the usual console/`rdinit=/init`, `lsm=bpf` where needed, and `as_native_smoke=1`. QEMU TCG may be launched by an ordinary host UID with access to the exact kernel image; the guest itself runs real root and loads its modules. This is distinct from a broker execution receipt. This script never loads anything on the host. `/init` mounts its virtual filesystems, loads the guest module, and invokes `/suite/native_smoke --guest-diagnostic /suite`. The output includes the actual kernel, source and artifact SHA-256 digests, each independent subject's PID/open result/errno, Native receipts, and retirement events. Check `AS_NATIVE_SDK_SMOKE_PASS diagnostic_ordinary_file_only` and `AS_NATIVE_SDK_GUEST_EXIT=0`; a successful helper exit alone is not a successful original operation.

The small fixed sequence covers direct Allow/Deny, binding a real ToUser original before release, a bound Deny fallback, unbound expiry as an error, an old held generation surviving replacement until its actual retirement, temporary overrides surviving persistent replacement, explicit Resume, and natural Quiesce with no status-query polling. `fd_loss` then kills an actual controller, confirms its loader exited and a fork child still owns the Native FD, and independently attempts a ToUser-protected open. It requires real `EIO`, then explicitly reconnects, initializes and drains the driver to retire its own pins. Source failure is never inferred solely from closing the last FD.

The diagnostic follows the current subject CLI and native layouts only. Its normal phase observes the same consumer task's actual completion; it adds no tester deadline to original operations or retirement. Native hold and explicit review-rule deadlines remain separate source contracts. After recovery, release the drained control connection before requesting BPF link retirement, matching the formal DriverSession shutdown order. See the [scoped refactor evidence](../../docs/evidence/driver-boundary-audit-20261115.md).

The same control lifecycle diagnostic also leaves a real Direct record unread before requesting Quiesce. It records each received native event byte for byte and checks that the record precedes the actual drain reply. After that reply, another matching operation still exercises the adopted Deny while the stopped observation source produces no new queue tail. Classification happens after real resource cleanup; no tester timer cuts off these operations.

`source-sha256.json` identifies source bytes at packaging and all copied/built fixture bytes. Freeze source compilation before packaging when using the result as integrated evidence. Packages and previous evidence are kept; pass a new output directory for another build.

## Formal MainAssembly and file self protection

`package-main.sh NEW_OUTPUT_DIRECTORY CURRENT_NATIVE_BUILD [STATIC_BUSYBOX] [CARGO_TARGET_DIRECTORY]` builds the actual MainAssembly and Linux adapter as a static executable under `/as/bin/as-service`, with the fixed configuration and rule files. The formal package also copies `as_flow.bpf.o` and `as-tls-ingress` from the same Native build. Both package scripts accept an explicit shared Cargo target directory (or `CARGO_TARGET_DIR`) while copying independent guest artifacts into each new output directory. The Linux Cargo configuration and static build flags select the locked getrandom library's `linux_getrandom` backend; no fixed random seed, random-device allowlist or custom entropy implementation is used.

Boot this image with the same matching kernel, `rdinit=/init`, BPF-LSM enabled, and `as_native_main_smoke=1`. The formal path uses the configuration owner's real self-protection requirement. It exercises direct Allow/Deny, a retained original and authenticated answer, bound timeout, no-frontend behavior, real configuration persistence and native adoption, and actual shutdown. The frontend and log consumers are test media; log queue delivery does not claim durable storage.

An independent probe prepares writable FDs, an external hard link and a read-only shared mapping before activation. After activation it attempts writes through both old FDs, a new writable shared mapping, mprotect, chmod, xattr changes, a write-open through the external alias, create, rename and unlink. It verifies actual errno and unchanged file bytes, attributes and names. It does not test revocation of an already writable mapping.

The same static service is then started again after healthy shutdown. Before deliberate controller exit it changes the broad file Allow to ToUser through the real authenticated rule writer. Only exact test dependencies remain allowed: BusyBox opening the independent subject and its own executable, and the service reading the guest marker. The independent subject must receive EIO after source failure; a fresh execution of the same service must recover through the production maintenance path, with no broad AS or loader read allowlist.

Require `AS_MAIN_NATIVE_SMOKE_PASS`, `AS_MAIN_COLD_RECOVERY_PASS`, `AS_MAIN_NATIVE_MODULE_UNLOADED` and `AS_MAIN_NATIVE_GUEST_EXIT=0`, plus actual guest/QEMU exit and process cleanup. When a broker is used, its subject/scope/supervisor receipt is recorded separately; an ordinary-UID QEMU run does not fabricate those broker fields. Source and artifact identities are recorded in `source-main-sha256.json`. The current formal suite also exercises real process/network Allow/Deny and actor/parent termination, DriverTools, process-tree fields, controlled IPv4 ingress and a TLS/phantom/chat software-provider pipeline. Its source/recorded output determines the actually executed subset; no capability is inferred from an enum or a helper exit. It does not prove other architectures, package installation, MCP parsing, independent container ingress, process-tree persistence or real OpenClaw acceptance.
